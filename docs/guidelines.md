# Coding guide: plugin-owl (v2)

How code in this repo is structured and written. It applies `onepeek-docs/standards/code-guidelines.md` to the Claude Code plug-in. The spec is the LLD `onepeek-docs/architecture/lld/clients/worklog-plugin.md` and the contract `contracts/openapi/ai-plugin.yaml`. This repo is **public**: everything here can be read by anyone.

## 1. What the plug-in does (and never does)
- Hooks only enqueue. A background helper (started detached by the hook) turns each finished session into one record: exact usage numbers, commit hashes with diff stats, and (only with the person's yes) a cleaned summary written by the person's own Claude Code under a fixed prompt. It signs, chains, holds 10 minutes, then sends over HTTPS.
- It never sends source code, diffs, commands, prompts, raw replies, secrets, paths, repository or host names, emails or names. Free text exists in exactly one place: `insight`.
- No command, skill or hook accepts content from the person. The controls are ON, OFF, PAUSE, RESUME and DISCARD, global or per project.
- It never gets in the way: every failure is silent to the session, and a hook always exits 0.

## 2. Folders
```
.claude-plugin/plugin.json   manifest (hooks auto-discovered, skills only, no MCP server)
hooks/hooks.json             SessionStart, Stop, PreCompact, SessionEnd -> dist/src/hook/enqueue.js
skills/onepeek-*/SKILL.md    the person-only commands (disable-model-invocation)
prompt/summary.v1.txt        the fixed prompt; its sha256 is in every record
src/hook  src/usage  src/summarise  src/clean  src/record  src/sign  src/keystore  src/spool  src/auth  src/send  src/cli  src/state
evals/    the 30 sessions (JSON, generated by evals/gen/make.py), the judge and the runner
tests/    unit, privacy, injection (50 transcripts), latency, eval harness
scripts/  build.mjs (tsc + build-info), lint.mjs (CI rules)
```
- `send/` is the ONLY module that imports a network API (lint rule). `contract.ts` there holds every path and reason code.
- `record/` builds records by allow-list from named fields; `schema.ts` validates and refuses unknown fields.
- `clean/` holds the text rules (same rules as the server), gitleaks-style secret shapes and the taint check on the model's input.

## 3. Rules
- Node standard library only; no runtime dependency. Dev dependencies are pinned and at least 7 days old.
- The only environment variables read are those the LLD names plus the system ones the lint allow-list lists.
- No telemetry, no other network call, no fallback host, no reading of managed settings, MDM, firewall or proxy configuration.
- Secrets are never written to this repo; test secrets are assembled at run time (`tests/helpers/canary.ts`).
- A change to `prompt/summary.v1.txt` changes the prompt hash: it needs a new eval run, and the server allow-list must learn the new hash.

## 4. Tests
- Privacy and injection tests gate every merge: hostile fixtures must never put a planted secret on the wire in any encoding.
- The eval (`npm run eval`) gates a release: 27 of 30 sessions pass every criterion, 0 leaks.
- Each rule id (AIP-*) in the LLD names a test; keep the names.
- The eval set (`evals/sessions`) is HELD OUT: written by a separate author who never saw the prompt. Prompt work uses
  only `evals/dev` (`npm run eval -- --set dev`); no prompt example may come from the held-out set. The judge is a
  different model from the summariser (opus judges sonnet); `evals/results/latest.json` records the resolved model
  ids, CLI version, prompt, judge and set sha256 and the date.

## 5. Accepted limits (stated, not hidden)
- Consent: the question needs a real interactive terminal, an explicit `yes` and a confirmation word chosen at random
  and typed back; typed-ahead (piped) input never counts. A program that drives a pseudo-terminal, reads the screen and
  types the word can still answer. The backstop is the server-side consent record, shown and changeable in the web app.
- Transcript source (AIP-H2.8): only `<CLAUDE_CONFIG_DIR>/projects/**/<session_id>.jsonl` is read. Code that runs as
  the person can write there or start the hook with its own `CLAUDE_CONFIG_DIR`; this narrows the path, it does not
  make a crafted transcript impossible (LLD §11: a prompt-injected session has the person's powers).
- The cleaner catches shaped secrets and anything the session itself held (taint); an unshaped secret the model invents
  without it ever appearing in the session cannot be recognised. People and company names are caught only when learned
  or blocklisted. A generic tool file name such as Dockerfile is allowed.
- Key store: macOS keychain, Linux Secret Service (user-only file only when none answers at first use), Windows DPAPI.
  Once a store is chosen, or a vault or spool exists, a failed read stops with "key store unavailable": no new key.
